# 2.6.0

## Owner-directed suggestion replacement

- When the owner replaces a surfaced hiring suggestion with a different role ("actually just hire a software developer instead"), the Chief now withdraws the superseded recommendation, records the replacement at priority 1 as a provisional recommendation, and replies with one short sentence naming the new role.
- The replacement suggestion appears even when the confirmation does not repeat the role title verbatim: the runtime attaches the Marketplace action for a recommendation that first appears during the turn, and keeps attaching it when the reply names the role.
- The superseded suggestion is retired rather than left clickable. Its widget renders as a muted "Cancelled - replaced by <role>" tile with no action button, and the new role gets its own suggestion widget. Withdrawing a recommendation without a replacement cancels its widget outright.
- A suggestion request for a role that is already surfaced returns the existing widget instead of stacking duplicates, and creating a new suggestion retires earlier pending ones in the same conversation. Multi-role suggestions created together (for example, from one approved resource change) keep their single grouped carousel.

## Reliability

- Optional executive follow-up steps (default product-manager validation, hiring personal-todo sync, product-manager context pushes) can no longer replace a committed reply with the platform's generic failure message. Failures are logged as warnings and the response stands.
- Hiring personal-todo synchronization now skips with a warning instead of failing the turn when the employee identity is temporarily unavailable.

## Configuration and permissions

- No new capability grants are requested. Existing installations do not need to approve additional access to receive the replacement behavior.
