# 2.17.0

- Leadership coverage assessments are read with `AgentModelJson.ReadAsync` (SDK 5.21.1). Previously a rejected reply
  was answered with a fixed note ("The previous result did not satisfy the public JSON contract") that showed the
  model neither its answer nor the reason. Now the model gets its previous answer and the exact problem: an empty or
  overlong rationale, evidence identities that are not active assignments (listed), an unknown next action, a Hire
  for a human-required need, or a hiring role outside the allowed roles (listed). Still two model calls at most.
- A missing evidence list is treated as empty. Clarifications still never assert unproven ownership, and only a Hire
  keeps role fields.
- When both attempts fail, the Blocked result's rationale now ends with the last problem.
- SDK 5.9.0 to 5.21.1 for package builds (local builds already use the sibling checkout). No grant or manifest change.
